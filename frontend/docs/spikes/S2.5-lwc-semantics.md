# S2.5 — lightweight-charts v5 semantics (spike)

Version in repo: **5.2.1**. Spike: `src/dev/S25Spike.tsx`, open `/?spike=lwc` (dev only). Delete the spike after S6.

Legend: **[T]** = stated by the v5.2.1 typings/docs. **[R]** = runtime behaviour, confirmed only by running the spike (fill the Result column; not verified in the authoring session — no browser was available).

## Findings

| # | Topic | Finding | Source | Build rule for S4–S6 |
|---|---|---|---|---|
| 1 | time → x | `timeToCoordinate(time)` returns `null` if the time is not on the time scale. | [T] | Never assume a number. Snap to a real bar time first (nearest-bar), then convert. |
| 2 | time → index | `timeToIndex(t, findNearest?)`: exact by default, nearest when `true`; `null` if not found. | [T] | Use `findNearest=true` for crosshair snapping; use exact for "is there a bar here". |
| 3 | x → time | `coordinateToTime(x)` returns the time of the bar at x, `null` if no bar there. | [T] | Hover time = bar time, never raw pixel time. Off-data x ⇒ null ⇒ clear crosshair. |
| 4 | Weekend/missing bars | The scale is index-based (logical), not wall-clock: gaps have no x. | [T]+[R] | Boundaries inside a gap cannot be drawn by `timeToCoordinate`; use `makeCoordinates` extrapolation (`chartApi.coordinates`) or snap to the next real bar. |
| 5 | `setCrosshairPosition` | Signature `(price, horizontalPosition, series)`. A price and a series are both required. | [T] | In S5 pass the hovered chart's price (or the target series' last close when the source is another TF) plus the target chart's candle series. |
| 6 | Crosshair re-entrancy | Does `setCrosshairPosition` fire `subscribeCrosshairMove` on the same chart? | [R] | Always guard with an `applyingCrosshair` flag regardless; probe tells us whether it is needed. |
| 7 | Off-grid time in `setCrosshairPosition` | Whether a time between target bars snaps to nearest or is ignored. | [R] | Snap ourselves to the target's nearest bar before calling. |
| 8 | Range APIs | `setVisibleRange({from,to})` "cannot extrapolate": it clamps to existing data. `setVisibleLogicalRange` can go beyond data (negative/over-length logical indexes). | [T] | Viewports (S3) must use **logical** ranges derived from bar indexes; use time range only inside data. |
| 9 | Range events | `subscribeVisibleLogicalRangeChange` fires for programmatic and user changes. | [T]+[R] | Two-way linking needs the `applyingRange` origin flag + debounce (S3). Probe prints the callback count unguarded vs guarded. |
| 10 | Multi-instance | One chart per TF; each owns its own time scale; sizes/`barSpacing` differ per chart. | [T] | Sync by **time (focus)**, never by copying logical ranges between charts of different TFs. |
| 11 | Replay / `asOf` | `series.setData(truncated)` replaces the data; the visible range is not guaranteed to follow. | [R] | On `asOf` change: truncate known bars (close ≤ asOf), then re-apply the viewport explicitly. Nothing future may reach `setData`. |
| 12 | Crosshair event data | `MouseEventParams.time` is `undefined` outside available data; `point` undefined on mouse-leave. | [T] | Treat `time === undefined` or `point === undefined` as "clear shared crosshair". |

## Decisions carried into S3–S6
1. Focus is time-based; every chart derives its **own logical range** from `ViewportPolicy` + its own bar array.
2. All cross-chart effects (range, crosshair) go through one origin flag + debounce (30–60 ms).
3. Crosshair snaps per chart to nearest real bar; clear on `time === undefined`.
4. Boundaries and shading use extrapolating coordinates (`chartApi.coordinates`) so gaps and forming parents still place correctly.
5. Replay never passes bars with `time + tfSeconds > asOf` to `setData`.
