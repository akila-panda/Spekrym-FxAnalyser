## Findings
1. **Projection starves on lower TFs.** H1/M15/M5 show 0 projected objects at every level: native objects fill each layer cap first (projected rank last), so HTF context and MTF confluence areas almost never reach the chart. Areas/contradictions appear only on H4 Advanced.
2. **Detection volume is high before caps.** Raw objects per TF: D 5,502 (4,200 reference levels, mostly round numbers), M1 3,057, M5 3,030, M15 2,922, H1 2,613, H4 1,490. Candle signals (355–777) and FVGs (340–808) dominate. Hidden by caps, but relations are capped at 300 candidates.
3. **Perf (cold, test env):** all detectors per TF D 431 ms · H1 297 ms · H4 273 ms · M15 249 ms · M1 236 ms · M5 154 ms. Above the 150 ms budget for 5,000 bars; memoised after first run. DK2 rule: Web Worker if demanded.
4. **Defaults to approve (§D, OQ-6):** unchanged so far; no evidence yet that any threshold is wrong, but FVG `minAtr` 0.25 and candle-signal `locAtr` produce the highest counts.

## Decisions needed
- A. Reserve a projected quota per layer (proposal: up to 2 of the cap) so HTF context shows on M15/M5. Default: yes.
- B. Round-number reference levels: emit only within the relevance window instead of the whole history. Default: yes.
- C. FVG `minAtr` 0.25 → 0.5. Default: keep until real data (OQ-5).
- D. Perf: move detection to a Web Worker now, or at DK21. Default: DK21.

## Applied (defaults A, B; C keep; D at DK21)
- A: `layers/projection.ts` reserves `PROJECTED_QUOTA` = 2 projected slots per layer (Minimal: 1 of 3 total); spare slots fall back to natives. Presentation constant, not a methodology param, so `rulesVersion` is unchanged.
- B: view-time, not detection-time. A detector cannot see the latest price without breaking the no-lookahead contract, so round-number `reference_level`s (native too) pass `isRelevant` (3 × ATR of price) in `selectForView`. Raw detection volume is unchanged.
- Tests: `layers/g2.test.ts`.
